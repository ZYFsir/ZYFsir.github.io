无论需求大小，每次agent都需要从头访问一遍代码库结构，这就是消耗token又影响agent工作表现。

因此有以下优化方式

## [AGENTS.md](http://AGENTS.md) 手动文档管理

手动编写文档\\组织docs文档库的方式实现必要信息的暴露。好处时每一处文档间的引用都可以添加上足够的语言解释，agent能够有明确的查找方向。

难点是“功能 - > 文件”的映射。代码修改需要文档的同步修改维护。

ai自动编写的文档在精简性，提供有效信息方面还不太行，尤其涉及到功能的变更\\互相冲突的信息时，自己编写的文档会造成其他agent的误会。agent a的决策会被agent b奉为圭臬。

## 建立代码索引，替换掉搜索工具

在极简工具集的情况下，ai通常依靠文本搜索工具grep查找自己想要的内容。带有盲目性，会在还没了解整个项目的情况时，就钻进具体的搜索到的结果中进行开发，但好处是实时探索，不会有过时问题，而且搜索范围覆盖整个项目。

使用tree-sitter 解析 AST 则加快搜索速度。

## 自动生成上下文包

根据任务提前进行一轮固定格式的调研，汇总信息：

- 最相关文件列表
- 关键接口和调用链

## 历史经验做记忆

### **推荐落地路线**

1. **最小可行**：`AGENTS.md` + 目录地图 + 常见任务定位表 + 代码搜索 + 任务模板。

2. **进阶**：tree-sitter 生成 repo map + 语义检索 + MCP 工具。

3. **高级**：代码知识图谱 + 向量库 + 历史 PR 记忆 + 自动上下文包。

衡量指标：定位时间、首次命中相关文件准确率、PR 返工率、agent token 消耗。最有效的组合是：**自动生成 repo map + 混合检索 + Agent 启动强制读 AGENTS.md + 按需工具查询**。纯文档一定会腐烂，索引和地图必须尽量自动更新。
